# 집키미

직접 본 집을 비교해 고르고, 고른 집으로 계약 준비부터 입주 후 관리까지 한 번에 확인하는 서비스입니다. · 엘리스 AI 챌린지 PoC 목업

- 서비스: <https://first-home-rose.vercel.app/>
- 저장소: <https://github.com/Soeun1223/first-home>

> 등기부·특약 AI 분석 화면은 가상 데이터로 만든 예시입니다. 법률 자문이 아니며, 실제 계약 전에는 출처의 공식 안내와 전문가에게 확인하세요.

## 한눈에 보기

머리글의 탭 두 개가 하나의 흐름으로 이어집니다.

```
① 매물 비교                         ② 계약 준비
보고 온 집 추가 → 체크리스트 작성 →  [이 집으로 계약 준비] →  금액이 채워진 계약 가이드
카드로 판정·점수·비용 비교                                     타임라인 · STEP 1~4 · 캘린더 구독
```

## 주요 기능

### ① 매물 비교

- 보고 온 집의 이름, 보증금, 월세, 관리비를 넣고 3단계 체크리스트를 채웁니다.
  - **1단계 필수**(전입신고, 확정일자, 등기부, 소유자 일치, 건축물대장): 점수 없이 **통과 / 보류 / 탈락**만 판정
  - **2단계 중요** 80점, **3단계 있으면 좋음** 20점 → 100점 만점과 S·A·B·C 등급
- 비교 카드는 통과 → 보류 → 탈락 순으로 묶고 같은 판정 안에서 점수순으로 정렬합니다. 통과한 집 중 최고 점수에 ‘추천’이 붙습니다.
- 위치(동네, 학교·역까지 도보 시간)는 점수에 넣지 않고 카드 아래에 참고로만 보여 줍니다. 번지·호수 같은 상세 주소는 받지 않습니다.
- 고르는 즉시 자동 저장되고 “✓ 저장했어요” 알림이 잠깐 떴다 사라집니다.

### ② 계약 준비

- 계약 예정일과 입주일을 넣으면 STEP 1~4(계약 준비 → 계약서 검토 → 잔금·입주 → 입주 후 관리)에 필요한 일을 날짜순 타임라인으로 정리합니다.
- 임대차 신고 대상 여부, 대항력 발생일, 반환보증 신청 마감, 월세 세액공제를 내 금액·지역 기준으로 계산합니다.
- 등기부등본, 대항력 같은 용어를 누르면 뜻과 함께 **“내 계약에서는”** 설명이 펼쳐집니다. 모든 안내에 공공기관·법령 출처 번호가 붙어 있습니다.
- 등기부·특약 AI 분석은 파일 올리기 → 분석 단계 → 결과 흐름을 보여 주는 목업입니다(파일은 서버로 보내지 않습니다).

### 두 기능 잇기: 이 집으로 계약 준비

- 매물 카드나 매물 체크리스트 화면에서 **이 집으로 계약 준비**를 누르면 그 집의 보증금·월세·관리비가 계약 가이드에 채워지고 ② 탭으로 넘어갑니다(월세가 0이면 전세로 바뀝니다).
- ② 탭 맨 위 **계약 준비 중인 집** 카드에 매물 체크리스트의 필수 5개 결과가 이어지는 STEP과 함께 보입니다. 예: `문제 있음 · 등기부등본에 큰 근저당·압류가 없는가 → STEP 1 등기부등본 확인`. 탈락한 집이면 경고가 뜹니다.

### 저장과 캘린더 구독

- 계약 준비 내용은 링크를 만들지 않아도 이 브라우저에 자동으로 남습니다.
- **이 계약 저장하고 링크·캘린더 받기**를 누르면 `?plan=코드` 링크가 생기고, 다른 기기에서 그 링크로 다시 열 수 있습니다. 이후 고치는 내용은 자동 저장됩니다.
- 저장하면 **내 캘린더에 일정 구독** 버튼(아이폰·맥 캘린더, 구글 캘린더, 주소 복사)이 나타납니다. 계약일, 임대차 신고 마감, 잔금·입주·전입신고, 대항력 발생, 전입신고 기한, 반환보증 마감, 월세 세액공제, 갱신 요구 시작·마감, 계약 만료가 쓰던 캘린더에 들어가고, 할 일마다 3일 전·전날 오전 9시 알림이 붙습니다. 집키미에서 날짜를 고치면 캘린더 앱이 다시 읽을 때 따라 바뀝니다.

## 데이터는 어디에 있나

| 데이터 | 저장 위치 | 누가 보나 |
|---|---|---|
| 매물(이름·금액·체크 결과·위치 참고) | 브라우저 `localStorage` (`zipkimi:listings:v1`), 고른 집 id는 `zipkimi:chosen` | 이 브라우저에서만. 서버로 보내지 않습니다 |
| 계약 준비 임시 저장 | 브라우저 `localStorage` (`zipkimi:contract:v1`) | 이 브라우저에서만 |
| 저장한 계약(계약일·입주일·유형·보증금·월세·지역·기간·총급여·체크 상태) | Supabase `plans` 표 | 코드를 아는 사람만. 브라우저는 표에 직접 닿지 못하고 Vercel 함수가 secret 키로만 읽고 씁니다. 매물 이름은 저장하지 않습니다 |
| 용어집 21개 | `terms.json` | 공개(자주 바뀌지 않는 데이터라 파일 하나로 둡니다) |
| 매물 체크리스트 항목 27개 | `data/checklist.json` | 공개 |

저장 링크와 캘린더 주소는 코드를 아는 사람이면 열 수 있으므로 다른 사람에게 보내지 않도록 화면에서 안내합니다. 글꼴(Pretendard)은 jsDelivr CDN에서 받아 오며, 이때 일반 접속 정보만 전달됩니다.

## 구조

**화면 (정적 파일)**

| 파일 | 하는 일 |
|---|---|
| `index.html` | 머리글(① 매물 비교 / ② 계약 준비 탭), 매물 비교·매물 체크리스트 화면, 계약 준비 화면 |
| `listings.js` | 매물 추가·검사, 3단계 체크리스트 점수, 비교 카드, 화면 전환(`#/`, `#/listing/id`, `#/contract`), 고른 집 요약, 저장 알림 |
| `contract.js` | 계약 날짜 계산, 타임라인, STEP 1~4, 용어 펼치기, AI 분석 목업, 링크 저장, 임시 저장, 캘린더 구독 버튼 |
| `style.css` | 원룸 매물 체크리스트 디자인 기준으로 통일한 스타일(계약 준비 규칙은 `.cv` 안에서만), 밝은·어두운 모드 |
| `data/checklist.json`, `terms.json` | 매물 체크리스트 항목, 용어집 |

**서버 함수 (Vercel)**

| 파일 | 하는 일 |
|---|---|
| `api/plans.js` | `POST/GET/PUT /api/plans` · 계약을 코드 하나로 저장하고 다시 엽니다 |
| `api/calendar.js` | `GET /api/calendar?code=코드` · 저장한 계약을 읽어 계약 일정을 iCalendar(`text/calendar`)로 돌려줍니다 |

**공통 로직과 데이터베이스**

| 파일 | 하는 일 |
|---|---|
| `lib/plan.js` | 저장할 계약 입력 검사(모르는 필드는 버리고 틀린 값은 고칠 방법을 알려 줌), 저장 코드 만들기 |
| `lib/schedule.js` | 계약 일정 계산. 화면 타임라인과 같은 규칙 |
| `lib/ics.js` | 일정 → iCalendar 글자(하루 종일 일정, 알림, 75바이트 줄 접기) |
| `lib/db.js` | Supabase 연결, 공통 오류 응답, JSON 본문 읽기 |
| `supabase/schema.sql` | `plans` 표. RLS는 켜 두고 공개 역할 정책은 만들지 않습니다(함수만 접근) |

## 시작하기

### 1. Supabase 표 만들기

Supabase 대시보드 → **SQL Editor**에서 `supabase/schema.sql`을 붙여 넣고 **Run** 합니다.

### 2. Vercel 배포

1. <https://vercel.com/new>에서 GitHub 저장소 `first-home`을 **Import** 합니다. Framework Preset은 **Other**로 둡니다.
2. **Environment Variables**에 두 값을 넣습니다(Supabase → Project Settings → API Keys / Data API).
   - `SUPABASE_URL`
   - `SUPABASE_SECRET_KEY` (서버 전용, 화면 코드에 넣지 않습니다)
3. **Deploy**를 누릅니다. 환경 변수를 나중에 바꿨다면 **Deployments → ⋯ → Redeploy** 합니다.

확인: ② 계약 준비에서 **이 계약 저장하고 링크·캘린더 받기**를 누르면 `?plan=코드` 링크와 캘린더 구독 버튼이 나타납니다.

### 3. 로컬에서 보기

```bash
npm install
npm test
npm run dev   # http://localhost:3000
```

`.env.example`을 `.env.local`로 복사해 값을 넣으면 로컬에서도 Supabase를 씁니다. 값이 없어도 매물 비교와 계약 준비 화면은 그대로 쓸 수 있고, 링크 저장과 캘린더만 오류를 알려 줍니다.

## 내용 고치기

| 고칠 것 | 위치 |
|---|---|
| 용어 뜻·출처 | `terms.json` |
| “내 계약에서는” 문장 | `contract.js`의 `MINE` (입력값으로 계산) |
| 매물 체크리스트 항목·단계·가중치 | `data/checklist.json` |
| 계약 일정 규칙(신고 기한, 갱신 기간 등) | `contract.js`의 `derive`·`renderTimeline`과 `lib/schedule.js`를 **함께** 고칩니다 |
| 출처 목록 | `contract.js`의 `SOURCES` |

CSS·JS를 고쳐 올릴 때는 `index.html`의 `?v=날짜` 값을 바꿔야 브라우저가 새 파일을 받아 옵니다.

## 알려진 한계

- 매물 기록은 브라우저 하나에만 있어서 휴대전화에서 체크한 매물을 PC에서 볼 수 없습니다. 계정 기반 동기화는 다음 단계 계획입니다.
- 캘린더는 앱이 주소를 다시 읽을 때 바뀌므로 몇 시간 늦을 수 있습니다. 아이폰은 구독 화면에서 ‘알림 제거’를 꺼야 알림이 울리고, 구글 캘린더는 구독한 캘린더 설정에서 알림을 따로 켜야 합니다.
- 계약 일정 규칙이 화면(`contract.js`)과 서버(`lib/schedule.js`) 두 곳에 있습니다. 시험이 서버 쪽 날짜를 확인하지만, 규칙을 바꿀 때는 두 곳을 함께 고쳐야 합니다.
- 등기부·특약 AI 분석은 가상 데이터로 만든 목업입니다.
- 제도와 기준(신고 대상 금액, 보증 한도, 세액공제 요건 등)은 바뀔 수 있습니다. 화면의 출처는 2026년 11월에 확인했습니다.
